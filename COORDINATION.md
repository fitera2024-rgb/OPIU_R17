# Координация работы

## Роли

- Текущий основной чат — единственный координатор: план, объединение изменений, тестирование и выпуск.
- Пользователь самостоятельно запускает Codex Spark только по подготовленной карточке задачи.
- Агенты выполняют независимые ограниченные аудиты и тесты; они не утверждают бухгалтерскую логику.

## Правило Spark

Каждая задача Spark должна содержать:

1. путь, версию и SHA-256 текущего контракта из `contracts/CURRENT.md`;
2. идентификатор и одну цель;
3. точные входные пути;
4. разрешённые для изменения файлы;
5. запрещённые действия;
6. затрагиваемые пункты контракта и проверяемые критерии PASS;
7. формат отчёта и перечень изменённых файлов.

Задача без блока `Контракт` имеет статус `BLOCKED` и не запускается.

Результат Spark не объединяется автоматически. Координатор проверяет diff, запускает тесты и только затем фиксирует commit.

## Новая ошибка пользователя

До изменения кода координатор добавляет ошибку в `contracts/ERROR_REGISTER.md`. Если замечание меняет или уточняет функциональное требование, выпускается новая версия DOCX и обновляется `contracts/CURRENT.md`. Устная договорённость не отменяет зафиксированный контракт.

## Если пользователь уходит

После сообщения пользователя «ухожу» координатор продолжает автономно:

- выполняет текущий утверждённый план;
- использует агентов для независимых задач;
- не расширяет бизнес-правила за пределы контракта;
- не публикует и не загружает проводки в 1С;
- фиксирует результаты, тесты и оставшиеся вопросы в `STATUS.md`.

## Запрет параллельных конфликтов

Два исполнителя не редактируют один файл одновременно. Интерфейс, R005, R001, тесты и упаковка выдаются как отдельные области ответственности.
