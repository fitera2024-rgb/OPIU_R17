## Результат

Статус: PASS.

- Доказанное экономическое направление с неполной физической идентичностью сохраняется как видимая строка `SPORNO`.
- Недоказанные физические поля загрузочного диапазона A:AA очищаются; организация сверки не подставляется как организация физической операции.
- `READY` требует все пять явно подтверждённых признаков физического доказательства; отсутствие хотя бы одного признака даёт fail-closed результат.
- Односторонний `STORNO` после точного повторного открытия остаётся только `SPORNO`; `READY` разрешён только для сбалансированной пары `STORNO/REPOST`.
- Ошибка повторного открытия или повторное использование источника сохраняют доказанное экономическое направление как одну sparse-строку `SPORNO` с понятной причиной и пустыми недоказанными физическими полями.
- `STORNO` имеет отрицательный знак, `REPOST` — положительный; абсолютные суммы пары совпадают, итог пары равен нулю.
- Одна физическая строка ERP не может участвовать в разных парах.
- Финальный canonical-барьер отклоняет несбалансированную пару, включая случай `-100/+80`.
- Пользовательское поле `Содержание` не содержит `CaseID`, `PairID`, `SourceRowID`, `REPORT_ONLY`, SHA, путей и внутренних safety-параметров; аудит сохраняется отдельно.
- Пользовательские имена соответствуют §12.2: `[Организация][ДД.ММ.ГГГГ]_ОПИУ_ГОТОВО[_СПОРНО].xlsx`; неизвестный источник обозначается `ИСТОЧНИК НЕ ОПРЕДЕЛЕН`.
- Восстановлены требуемые API `buildMasterRegistry`, `scopedManifestRunIdentity`, `excludeHierarchyCoveredEconomicRows`; строки, уже покрытые доказанной hierarchy-authority, не материализуются повторно.
- Восстановлен fail-closed арбитраж пересекающихся hierarchy-authority без потери независимых аналитических оснований.
- Два абсолютных fixture-path заменены переносимым поиском внутри репозитория; async hierarchy-тесты действительно ожидают результат.

## Изменения тестов

Implementation-coupled ожидания изменялись только там, где они противоречили контракту или проверяли буквальный текст реализации:

- счёт физической операции при REPOST больше не меняется `44.1 → 26`; меняется только статья/код;
- тест разделения READY/SPORNO использует две разные физические строки, а не повторно одну;
- понятный статус `требуется подтверждение пользователя` проверяется вместо обязательного буквального слова `спорно`;
- проверка аналитической политики выполняется по результату и закрытым safety-gate, а не по фрагментам исходного кода.
- старые ожидания одиночного `READY` заменены обязательным `SPORNO`, даже после успешного reopen;
- group-scoped предложения без полного reopen не отображают физические поля как доказанные;
- технические audit-ID проверяются отдельно и запрещены в пользовательской колонке P.
