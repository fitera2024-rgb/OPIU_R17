## Завершённый функциональный контур

- production-цепочка остаётся прямой: `R005 → immutable handoff → R001`; скрытый Rules Service не участвует;
- месячная область закреплена как одна организация + один полный календарный месяц `YYYY-MM`; годовой файл или ZIP допустим только как контейнер выбранного месяца;
- R005 допускает детерминированную цель внутри доказанного блока Инталев, выводит физический периметр организаций из authoritative ERP-иерархии, отделяет экономический блок физического счёта от presentation-размещения и показывает доказанную cross-journal ERP-операцию в основном дереве;
- R005-025 сохраняет exact physical ERP evidence в раскрываемом основном дереве без изменения финансовой authority, сумм и no-reuse guards;
- October owner golden, month-only enforcement, approval scope isolation, R005→R001 handoff и пользовательский lifecycle результата реализованы в release-базе и подлежат повторному подтверждению единым финальным gate.

## Оставшийся финальный gate

Финальный выпуск допускается только после одного свежего протокола на exact release commit. Непосредственно перед gate исполнитель получает exact tested SHA из Git командой `git rev-parse HEAD`, подтверждает его равенство `git rev-parse origin/release/r17` и записывает фактически проверенный SHA во внешний gate-протокол и release-manifest:

1. свежий прогон `3 Сахалин / 2025-01`: R005 → immutable handoff → R001;
2. golden-прогон `9 Управляющая компания / 2025-10` с подтверждением эталонных R005/R001 результатов;
3. month-only gate: `YYYY-MM` принимается, `YYYY`, `YYYY-QN` и многомесячный диапазон отклоняются, годовой источник используется только как контейнер;
4. полный release test suite и independent verifier;
5. детерминированная A/B-сборка переносимого пакета из одного exact commit;
6. relocation smoke из нового короткого пути;
7. финальные manifest, inventory и SHA-256 для release-артефактов.

## Неизменные ограничения безопасности

- `REPORT_ONLY=true`;
- `rules_service=false`;
- `posting_rows=0`, `executed_posting_rows=0`, `live_posting_rows=0`;
- автоматическая загрузка или проведение в 1С запрещены;
- финансовая строка требует доказанной физической строки ERP;
- одна физическая строка ERP не может повторно использоваться в финансовых корректировках;
- STORNO и REPOST равны по абсолютной сумме, итог пары равен нулю;
- исходные файлы не изменяются.

## Нельзя считать релиз готовым

- пока не завершены все семь шагов финального gate на одном exact commit;
- если manifest, inventory или SHA-256 не совпадают с фактически проверенными артефактами;
- если нарушен любой safety-инвариант, физическое ERP-доказательство или запрет повторного использования строки;
- если POST-R17 работа ошибочно включена в release scope.
