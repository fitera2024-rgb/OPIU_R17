# R005 — произвольный период и раскрытие до операций ERP

Изолированный REPORT_ONLY-кандидат поверх R004. Он добавляет выбор месяца, квартала или года и раскрывает строки ОПИУ по схеме:

`блок → подблок → статья → деталь → физическая операция ERP`.

Сборка не создаёт загрузочные проводки, не изменяет mappings/справочники и не работает с 1С.

## Runtime delta относительно R004

- `arbitrary_period_operation_evidence.mjs` — помесячная привязка журнала, операции и кандидаты `PairID`;
- `full_operation_evidence.mjs` — чтение точных строк журнала;
- `opiu_reconcile.mjs` — режимы `month`, `quarter`, `year`, source binding и построение дерева;
- `run_workdir.mjs` — уникальная рабочая папка каждого процесса;
- `opiu_ui.ps1` — выбор режима, периода и организации.

Остальные зависимости берутся из проверенной R004-базы. Порядок интеграции описан в `INTEGRATION.md`.

## Периоды

- месяц: `2025-07`;
- квартал: `2025-Q3`;
- год: `2025`.

Квартал и год всегда разбираются помесячно. `PairID` не может объединять строки разных месяцев.

## Безопасность

Все универсальные операции имеют класс `CANDIDATE_EXCLUDED`, исключены из финансовых итогов и не получают `UploadID`. В каждом результате сохраняются:

```text
posting_rows=0
ready_to_upload=false
release_allowed=false
```

Оранжевый `PairID` — только кандидат STORNO/REPOST для ручной проверки, а не готовая проводка.

## Подтверждённый QA

- июль: 518 операций, 38 веток, 3 `PairID`, 251 строка в парах;
- Q2: 1 547 операций, 114 веток, без `PairID`, только апрель–июнь;
- год: 6 027 операций, 456 веток, 9 `PairID`, 539 строк в парах;
- outline-уровни L1–L6 физически записаны в XLSX;
- `UploadID` и posting-строки отсутствуют;
- во входном журнале найдено 7 активных строк без физической суммы; 6 из них показаны в дереве под R036, все остаются fail-closed и не дают posting.

Это QA структуры и REPORT_ONLY-инвариантов, а не финансовый PASS и не разрешение на загрузку.
